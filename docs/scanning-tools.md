# Scanning, Linting & Security Tooling — Current State

This is a **current-state reference**, not a history — it says what's true right now. For _why_ each tool was chosen (alternatives considered, tradeoffs, cost), see [ADR-00009](./adrs/00009-linting-formatting-and-security-scanning.md) (the original matrix) and [ADR-00010](./adrs/00010-github-actions-supply-chain-hardening.md) (GitHub Actions pinning + `zizmor`). The ADRs don't get rewritten as tools are added or reconfigured; this file does.

**If you add, remove, or reconfigure a scanning/linting tool, update this table in the same commit.** That's the whole point of it existing — see the convention in `AGENTS.md`.

## Known gaps (tracked, not silent)

- **`@nx/enforce-module-boundaries` is currently permissive** — `depConstraints` allows any tag to depend on any tag. Real boundaries need real tags once `packages/*` exist to enforce against.
- **`ci.yml`'s `main`/`security-warn` jobs don't `needs: zizmor`** — within one CI run, a reverted action pin could still execute in those jobs before the `zizmor` job fails it. Job-dependency + branch protection is deferred to a later pass (see `AGENTS.md`).
- **Semgrep/Bearer are warn-only by design for now** — promoting either to blocking is deliberate future work once their false-positive rate is proven low on this codebase, not automatic.
