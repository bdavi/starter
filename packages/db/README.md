# @starter/db

Postgres + Drizzle — the single source of truth for the database: client, schema, migrations. See [ADR-00011](../../docs/adrs/00011-database-technology.md).

## Usage

```ts
import { db, user } from "@starter/db";

const users = await db.select().from(user);
```

## Commands

Run from the repo root:

```
pnpm run db:generate   # drizzle-kit generate — SQL migration from schema changes
pnpm run db:migrate    # drizzle-kit migrate — apply pending migrations
pnpm run db:reset      # drop + recreate local Postgres, re-migrate (scripts/db-reset.sh)
pnpm nx test db
pnpm nx lint db
pnpm nx typecheck db
```

All of the above need `DATABASE_URL` set (see `.env.example` at the repo root) and Postgres running (`docker compose up -d`). `DATABASE_URL` is validated in `src/lib/env.ts` (via `@starter/config`'s `createEnvGetter` helper) — this package owns that var; nothing outside it needs to know it exists. See [ADR-00013](../../docs/adrs/00013-environment-config-scoping.md).

## Schema

`src/lib/schema.ts` is regenerated by Better Auth's CLI for the `user`/`session`/`account`/`verification` tables (`pnpm nx run auth:auth-schema` — see `packages/auth`) — don't hand-edit those. Non-auth domain tables get added here directly as real features arrive.

## Status

Auth tables only, for now. No `packages/domain` yet to model real business data against.
